# صفحه‌ی وضعیت پروژه

یک صفحه که می‌گوید پروژه در کدام مرحله است، چه کارهایی انجام شده، PRها دست چه کسی هستند و نتیجه‌ی بازبینی هر هفته چه بوده. هم برای منتور است و هم برای دانشجوها. خودش با هر بازبینی، PR و تغییر کار به‌روز می‌شود.

[فهرست مستندات](../../docs/README.md) | [تیم و تقسیم کار](../../docs/team.md) | [فهرست کارها](../../docs/backlog.md)

## ۱. کجا ببینمش

| چه چیزی | کجا |
|---|---|
| صفحه‌ی کامل، فارسی و انگلیسی | https://tecso-dev.github.io/sarmiz/ |
| خلاصه‌ی کوتاه | issue سنجاق‌شده‌ی «وضعیت پروژه» (برچسب `status-board`) |
| نوبت هر PR | برچسب‌های `status:needs-author`، `status:needs-mentor` و `status:approved` روی خود PR |
| خبر هر بازبینی | گروه تلگرام، وقتی ربات وصل شده باشد (بخش ۵) |

صفحه فقط چیزهایی را نشان می‌دهد که در ریپوی عمومی هم دیده می‌شوند: کارها، PRها، بازبینی‌ها و نام کاربری GitHub. رتبه‌بندی و سنجش فعالیت آدم‌ها در آن نیست.

## ۲. چطور به‌روز می‌شود

یک workflow به نام `status` (فایل <span dir="ltr">`.github/workflows/status.yml`</span>) این‌ها را انجام می‌دهد:

1. داده را با `gh` از GitHub می‌خواند: issueها، milestoneها، PRها و بازبینی‌ها.
2. صفحه را می‌سازد و روی GitHub Pages می‌گذارد.
3. issue سنجاق‌شده را فقط وقتی چیزی عوض شده باشد بازنویسی می‌کند.
4. روی هر PR باز دقیقاً یک برچسب نوبت می‌گذارد.
5. اگر چیز تازه‌ای شده باشد، به تلگرام خبر می‌دهد و بعد آخرین وضعیت را در شاخه‌ی `status-data` ذخیره می‌کند تا همان خبر دوباره نرود.

این workflow در این زمان‌ها اجرا می‌شود: باز یا بسته شدن یا تغییر issue، تغییر PR (باز شدن، push تازه، درخواست بازبین، بسته شدن)، هر بازبینی (از راه workflow کوچک `status-ping`)، هر push به `main` که این پوشه یا <span dir="ltr">`docs/status/`</span> را عوض کند، و هر ساعت یک بار برای اطمینان.

نوبت PR از روی بازبینی منتور حساب می‌شود، چون تأیید منتور شرط merge است:

| وضعیت | یعنی |
|---|---|
| `needs_mentor` | هنوز بازبینی نشده، یا نویسنده بعد از بازبینی push کرده یا دوباره بازبینی خواسته |
| `needs_author` | منتور تغییر خواسته و نویسنده هنوز چیزی push نکرده |
| `approved` | منتور تأیید کرده و بعد از آن push تازه‌ای نیامده |
| `draft` | PR پیش‌نویس است |

## ۳. فایل‌ها

| فایل | کارش |
|---|---|
| `config.toml` | تنظیم‌ها: ریپو، منتور، دانشجوها، تاریخ شروع هفته‌ی ۱ و اسم و هدف هر مرحله |
| `collect.py` | خواندن داده از GitHub |
| `model.py` | حساب‌وکتاب: هفته و روز، کارهای انجام‌شده، نوبت PR و رویدادهای تازه (همه‌اش تست دارد) |
| `render_site.py` | ساختن صفحه‌ی HTML دوزبانه |
| `render_issue.py` | ساختن متن issue سنجاق‌شده |
| `actions.py` | برچسب PR، issue سنجاق‌شده و پیام تلگرام |
| `build.py` | اجرای همه‌ی این‌ها |
| `telegram-setup.sh` | وصل کردن ربات تلگرام، فقط یک بار و فقط توسط ادمین |
| <span dir="ltr">`assets/fonts/`</span> | فونت وزیرمتن (مجوز OFL) که همراه صفحه بارگذاری می‌شود |
| <span dir="ltr">`tests/`</span> | تست‌های واحد |

[بازبینی هفتگی](../../docs/status/README.md) در فایل `docs/status/reviews.toml` ثبت می‌شود.

## ۴. اجرا و تست روی لپ‌تاپ

برای ساختن صفحه در یک پوشه‌ی موقت (به GitHub چیزی نمی‌نویسد، فقط `gh` باید وارد شده باشد):

</div>

```bash
python3 scripts/status/build.py build --out /tmp/status-site
```

<div dir="rtl">

بعد <span dir="ltr">`/tmp/status-site/index.html`</span> را در مرورگر باز کن. برای تست‌ها:

</div>

```bash
python3 -m unittest discover -s scripts/status/tests -v
```

<div dir="rtl">

## ۵. راه‌اندازی، یک بار و فقط توسط ادمین

**GitHub Pages.** این دستور Pages را روشن می‌کند و منبعش را GitHub Actions می‌گذارد:

</div>

```bash
gh api -X POST repos/Tecso-Dev/sarmiz/pages -f build_type=workflow
```

<div dir="rtl">

بعد workflow را یک بار دستی اجرا کن:

</div>

```bash
gh workflow run status.yml --ref main -R Tecso-Dev/sarmiz
```

<div dir="rtl">

**تلگرام (اختیاری).** در تلگرام با @BotFather یک ربات بساز و توکنش را بردار، ربات را به گروه اضافه کن و یک پیام در گروه بفرست. بعد این را اجرا کن:

</div>

```bash
bash scripts/status/telegram-setup.sh
```

<div dir="rtl">

اسکریپت توکن را بدون نمایش می‌پرسد، شناسه‌ی گروه را پیدا می‌کند، محیطی به نام `status` می‌سازد که فقط شاخه‌ی `main` می‌تواند از آن استفاده کند، توکن و شناسه را در همان محیط ذخیره می‌کند و یک پیام آزمایشی می‌فرستد. توکن را هرگز در چت یا issue ننویس.

> [!WARNING]
> اگر ربات وصل نباشد، workflow بدون خطا کار می‌کند و فقط به تلگرام چیزی نمی‌فرستد. بعد از وصل شدن، خبرهای قدیمی دوباره نمی‌روند؛ فقط خبرهای از آن لحظه به بعد می‌روند.

## ۶. وقتی چیزی خراب شد

| نشانه | کار |
|---|---|
| صفحه بالای ۳ ساعت به‌روز نشده و یک هشدار قرمز دارد | در GitHub به Actions برو و آخرین اجرای `status` را ببین |
| اجرا می‌گوید «Pages is not enabled» | دستور Pages در بخش ۵ را اجرا کن و workflow را دوباره بزن |
| برچسب‌های PR عوض نمی‌شوند | برچسب‌های <span dir="ltr">`status:*`</span> باید وجود داشته باشند (در خود ریپو ساخته شده‌اند) |
| پیام تلگرام نمی‌رود | `bash scripts/status/telegram-setup.sh` را دوباره اجرا کن |
| می‌خواهی همین الان صفحه عوض شود | `gh workflow run status.yml --ref main -R Tecso-Dev/sarmiz` |

## ۷. امنیت

- workflow همیشه کد `main` را اجرا می‌کند. کد هیچ PRی را checkout نمی‌کند و هیچ متنی از issue یا PR را داخل دستور shell نمی‌گذارد.
- توکن ربات فقط در محیط `status` است و فقط `main` به آن دسترسی دارد. شاخه‌ی دانشجو نمی‌تواند آن را بخواند.
- اسم کاربرها در پیام تلگرام لینک به پروفایل GitHub است، نه @mention، تا به کسی که فقط اسمش شبیه است پیام نرود.
- صفحه هیچ درخواستی به بیرون نمی‌فرستد و فونت را از خودش بارگذاری می‌کند.
