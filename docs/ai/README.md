## ۲. مدل‌های انتخاب‌شده

انتخاب مدل تصمیم باز شماره‌ی ۵ [مشخصات فنی](../SPEC.md) است. تا پایان هفته‌ی ۱ این جدول پر می‌شود:

| کار | مدل | نسخه | چرا | سخت‌افزار |
|---|---|---|---|---|
| ترجمه | تعیین نشده | | | |
| vision برای import | تعیین نشده | | | |
| embedding | تعیین نشده | | | |

بُعد بردار embedding در ستون `menu_chunks.embedding` ثابت می‌شود. عوض کردن مدل embedding یعنی migration و embed دوباره‌ی همه‌ی منوها، و عوض کردن هر مدل یعنی اجرای دوباره‌ی همه‌ی ارزیابی‌ها و ثبت عدد تازه.

## ۳. ساختار پیشنهادی `evaluation-week1.md`

1. **خلاصه:** تصمیم «برو یا نرو» برای ساخت منو از عکس، و مدل‌های پیشنهادی، در سه خط.
2. **داده:** ۵ منوی واقعی (بدون نام کسب‌وکار)، تعداد آیتم هر منو، و اینکه جواب درست چطور تهیه شد.
3. **روش:** مدل‌های نامزد، سخت‌افزار، prompt استفاده‌شده، و نحوه‌ی تبدیل تومان به ریال.
4. **نتیجه‌ی خواندن عکس:** جدول برای هر منو و هر مدل: درصد آیتم‌های پیداشده، درصد قیمت‌های درست، درصد نام‌های درست، آیتم ساختگی، زمان و حافظه.
5. **نتیجه‌ی ترجمه:** جدول برای `en`، `ar`، `ckb` و `azb`: درصد «درست»، «قابل‌فهم» و «غلط»، با چند نمونه‌ی خطا.
6. **تصمیم:** «برو» یا «نرو» با آستانه‌ای که پیشاپیش گذاشته شده بود؛ اگر «نرو»، برنامه‌ی Excel.
7. **ریسک‌ها و سؤال‌های باز:** مثلاً نیاز به GPU یا ماشین جدا برای مدل.

| هفته | مجموعه | مدل و نسخه | تغییر نسبت به اجرای قبل | نتیجه |
|---|---|---|---|---|
| ۳ | نمونه‌ی ترجمه | | | درصد «درست» برای هر زبان |
| ۴ | ۳۰ سؤال دستیار | | | تزریق موفق، داده از کسب‌وکار دیگر، ردِ درست، جواب درست |
