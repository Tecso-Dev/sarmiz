# بازبینی هفتگی

بعد از هر بازبینی یا دموی هفتگی، منتور نتیجه را در [reviews.toml](reviews.toml) ثبت می‌کند. [صفحه‌ی وضعیت پروژه](../../scripts/status/README.md) همین فایل را می‌خواند و بعد از push خودش به‌روز می‌شود.

[فهرست مستندات](../README.md) | [طرح پروژه](../plan.md)

## ۱. هر هفته چه چیزی دارد

| فیلد | مقدار |
|---|---|
| `date` | روز بازبینی، مثل `2026-11-25`. تا بازبینی نشده خالی می‌ماند |
| `decision` | `pending` (هنوز نشده)، `passed` (برقرار)، `partly` (نیمه‌برقرار) یا `failed` (برقرار نیست) |
| `note_fa` و `note_en` | یادداشت کوتاه برای دانشجوها (اختیاری) |
| <span dir="ltr">`[[week.criteria]]`</span> | هر معیار پایان هفته یک بلوک دارد با `fa`، `en` و `status` |
| `status` | `pending`، `met` (برقرار) یا `not_met` (برقرار نیست) |

معیارها از [طرح پروژه](../plan.md) و صفحه‌ی هر هفته در <span dir="ltr">`docs/handoffs/`</span> کپی شده‌اند. اگر معیاری آنجا عوض شد، همین‌جا هم عوض کن.

## ۲. بعد از هر بازبینی

1. هر معیار را `met` یا `not_met` کن.
2. `decision` و `date` را پر کن و اگر خواستی یادداشت بنویس.
3. با یک commit روی `main` بفرست. صفحه و issue سنجاق‌شده خودشان به‌روز می‌شوند.

مثال: نتیجه‌ی بازبینی هفته‌ی ۱ وقتی بعضی معیارها برقرار شده‌اند:

</div>

```toml
[[week]]
n = 1
date = "2026-11-25"
decision = "partly"
note_fa = "محیط محلی و CI تمام شد؛ ورود با کد پیامکی هنوز مانده."
note_en = "Local environment and CI are done; login by SMS code is still open."
```

بقیه‌ی فیلدهای هفته (معیارها) همان‌طور که هستند می‌مانند و فقط `status` هر کدام عوض می‌شود.
