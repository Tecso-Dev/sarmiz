# سندهای تصمیم

هر تصمیم فنیِ مهم در سرمیز یک سند کوتاه دارد که می‌گوید چه تصمیمی گرفتیم، چرا، و چه چیزی را به جانش پذیرفتیم.

[فهرست مستندات](../README.md)

## ۱. چرا سند تصمیم

شش ماه بعد، کسی از دوره‌ی بعدی می‌پرسد «چرا پرداخت داخل سرویس `order` است و سرویس جدا ندارد؟». اگر جواب فقط در ذهن تیم قبلی بوده، یا تصمیم را بی‌دلیل عوض می‌کنند یا از ترس دست به آن نمی‌زنند. سند تصمیم جواب را نگه می‌دارد.

## ۳. کی باید سند تصمیم بنویسی

- وقتی می‌خواهی چیزی را در [مشخصات فنی](../SPEC.md) عوض کنی.
- وقتی یک وابستگی تازه بین سرویس‌ها اضافه می‌کنی.
- وقتی یک ابزار یا کتابخانه‌ی مهم انتخاب می‌کنی که عوض کردنش بعداً گران است.
- وقتی طرح جدول‌ها را از طرح پایه‌ی مشخصات فنی جدا می‌کنی.

برای تصمیم‌های کوچک، مثل نام یک تابع یا شکل یک کامپوننت، سند لازم نیست.

## ۴. قالب

فایل تازه را با شماره‌ی بعدی بساز، مثلاً `0008-<توضیح-کوتاه>.md`، و این بخش‌ها را پر کن:

</div>

```text
# <شماره>. <عنوان تصمیم>

| | |
|---|---|
| وضعیت | پیشنهادی / پذیرفته / کنار گذاشته / جایگزین‌شده با سند <شماره> |
| تاریخ | |
| تصمیم‌گیرندگان | |

## زمینه
چه مشکلی داریم و چرا الان باید تصمیم بگیریم؟

## تصمیم
دقیقاً چه کاری می‌کنیم؟

## گزینه‌هایی که بررسی شد
هر گزینه با خوبی‌ها و بدی‌هایش.

## پیامدها
چه چیزی آسان‌تر می‌شود، چه چیزی سخت‌تر، و چه خطری را پذیرفتیم؟

## کی دوباره بررسی شود
چه اتفاقی باعث می‌شود این تصمیم را دوباره باز کنیم؟
```

## ۵. قاعده‌ها

- سند پذیرفته‌شده را پاک نکن. اگر تصمیم عوض شد، سند تازه بنویس و وضعیت سند قدیمی را «جایگزین‌شده» کن.
- سند تصمیم در همان PR تغییر می‌آید، همراه با اصلاح مشخصات فنی و فصل مربوط راهنما.
- تصمیمی که روی چند بخش اثر دارد، تأیید منتور و همه‌ی آن بخش‌ها را می‌خواهد.
