# سند API

این پوشه سند OpenAPI همه‌ی مسیرهای REST سرمیز را نگه می‌دارد: `docs/api/openapi.yaml`.

[فهرست مستندات](../README.md) | [فصل ۶: API و قراردادها](../guide/06-api-and-contracts.md) | [قراردادهای proto](../../proto/README.md)

## ۱. چه چیزی اینجاست

| فایل | چیست | چه کسی می‌نویسد |
|---|---|---|
| `openapi.yaml` | توصیف همه‌ی مسیرهای <span dir="ltr">`/api/v1`</span> که `gateway` باز می‌کند | ابزار `buf` از روی فایل‌های proto؛ هیچ‌کس با دست |
| `README.md` | همین صفحه | تیم |

OpenAPI یک قالب استاندارد برای توصیف API روی HTTP است: مسیرها، ورودی‌ها، خروجی‌ها و خطاها در یک فایل.

## ۲. کی و چطور ساخته می‌شود

1. مرجع، فایل‌های proto و annotationهای HTTP آن‌هاست (بخش ۶ [مشخصات فنی](../SPEC.md)).
2. هر کس proto را عوض کند، کد را دوباره می‌سازد و `openapi.yaml` تازه را در همان PR commit می‌کند.
3. CI نسخه‌ی ساخته‌شده را با نسخه‌ی commit‌شده مقایسه می‌کند و اگر فرق داشتند خطا می‌دهد.
4. ابزار و تنظیم تولید را زوج پلتفرم در `W1-PA-3` می‌سازد. دستورش در بخش Commands فایل [AGENTS.md](../../AGENTS.md) می‌آید.

> [!WARNING]
> `openapi.yaml` را با دست ویرایش نکن. تغییر دستی در ساخت بعدی پاک می‌شود و CI هم آن را رد می‌کند. اگر چیزی در آن غلط است، proto را درست کن.

## ۳. کلاینت فرانت از اینجا ساخته می‌شود

اپ React نوع‌های TypeScript کلاینت API را از `openapi.yaml` می‌سازد (کار `W1-WEB-5`). پس وقتی یک فیلد در proto عوض می‌شود، کامپایلر TypeScript جاهایی از فرانت را که باید عوض شوند نشان می‌دهد. ابزار ساخت نوع‌ها را زوج فرانت در `W1-WEB-5` انتخاب می‌کند؛ جزئیاتش در [README فرانت](../../web/README.md) است.

## ۴. هنگام بازبینی PR

- [ ] اگر proto عوض شده، `openapi.yaml` هم در همان PR عوض شده است.
- [ ] diff فایل `openapi.yaml` فقط همان تغییری را نشان می‌دهد که انتظارش را داری.
- [ ] نام فیلدها `snake_case` است و پول در فیلدهای `_rial`.
- [ ] هیچ مسیر داخلی (مثل `PriceItems`) در سند دیده نمی‌شود.
